# CAM system kernel interface

**INCT_Kernel** - the CAM system kernel interface. The interface provides work with the NC program text and restarting the interpreter in the contour mode.

**Description of the interface methods:**

<table>
<thead>
<tr><th>Method</th><th>Method description</th><th>Description of use</th></tr>
</thead>
<tbody>
<tr><td><strong>Get_ProgramManager</strong></td><td>The function returns the interface for working with the NC program of the current operation (<a href="../nc-program-management/nc-program-management.md"><strong>INCT_ProgramManager</strong></a>).</td><td><ol><li>If the postprocessor generates several files for the current operation, this interface allows setting the order in which the NC program texts are passed to the interpreter.</li><li>To get only a part of the NC program text (for example, by labels in the program).</li></ol></td></tr>
<tr><td><strong>InterpreteContour</strong></td><td><p>The function starts a new interpreter instance to analyze the NC program text and get the contour.</p><p>Input parameters: <strong>NCProgram</strong> (<strong><a href="../nc-program-management/nc-program-management.md">INCT_Program</a></strong> interface) - NC program text; <strong>Contour</strong> (<strong>IUnknown</strong> interface) - contour interface.</p></td><td><p>If the generator built into the kernel (<a href="../../toolpath-construction/turning-machining-cycle/turning-machining-cycle.md">Turning machining cycle</a>) is not enough to form the tool path of a turning contour cycle (like CYCLE95 for the Sinumerik controller), a new copy of the interpreter can be started to get the geometry from the NC program of the contour path on your own. The <strong>InterpreteContour</strong> function is intended for this.</p><p>To form the contour geometry:</p><ol><li>Get the NC program text by the contour labels with the corresponding function (for example, <strong>GetPartByLabels</strong>).</li><li>Implement the <strong>Contour</strong> object, which must have an interface for passing and getting the tool path in the form and format the interpreter developer needs.</li><li>Call the <strong>InterpreteContour</strong> function and pass to it the objects obtained in the first and second steps (the NC program text of the contour and the <strong>Contour</strong> object).</li></ol><p>While <strong>InterpreteContour</strong> is executed, the CAM system gets a new <strong>INCT_Interpreter</strong> instance from the interpreter library, initializes the new interpreter, passes to it in the <strong>SetInterface</strong> method, in addition to the usual list of interfaces, the <strong>Contour</strong> interface, and translates and interprets the passed NC program text as in a usual interpretation. During the interpretation, the interpreter, knowing that it works in the contour mode (see <strong>Get_IsContourMode</strong>), must form the contour path with its own <strong>Contour</strong> object and the interface developed to store the geometric path.</p><p>After <strong>InterpreteContour</strong> finishes, the <strong>Contour</strong> object contains the geometric contour path ready to be used for forming the tool path in the primary interpreter instance.</p></td></tr>
<tr><td><strong>Get_IsContourMode</strong></td><td><p>The function returns the flag of whether the interpreter instance works in the contour mode.</p><p>Output parameter: (boolean) True - in the contour mode, False - in the tool path mode.</p><p>No input parameters.</p></td><td>If the interpreter starts its new copy itself (see <strong>InterpreteContour</strong>), the new interpreter instance must know in which mode it is started. If the new interpreter is started in the contour mode, it must form the contour geometry from the NC program text (see the <strong>Contour</strong> object). If the new interpreter is not started in the contour mode, it must form the tool path from the NC program text.</td></tr>
</tbody>
</table>

**INCT_Kernel2** - the CAM system kernel interface.

**Description of the interface methods:**

| Method | Method description | Description of use |
| --- | --- | --- |
| **DoSubprogram** | The method switches the translation and interpretation to the NC program text set by the **NCProgram** parameter, the number of times set by the **Count** parameter. After that, the translation of the NC program text continues from the place where it stopped.<br>Input parameters: **NCProgram** (**[INCT_Program](../nc-program-management/nc-program-management.md)** interface) - NC program (subprogram) text; **Count** (integer) - number of repetitions. | Used to execute subprograms (CALL for Sinumerik, M99 for Fanuc).<br>To get the subprogram text, use one of the following functions: **GetPartByLabels**, **GetPartByLabelsFromCurPos**, **GetPartByRegisters**. |
| **Log** | The method outputs a message to the CAM system log.<br>Input parameters:<br>**Msg** (string) - message text;<br>**MsgType** (**TNCMessageType**) - message type:<br>**nmtInfo** - information;<br>**nmtSuccess** - success;<br>**nmtWarning** - warning;<br>**nmtError** - error;<br>**nmtCritical** - critical;<br>**nmtException** - exception;<br>**nmtDebug** - debug. | Used to debug the interpreter. |
| **Notify** | The method outputs a message to the notification panel of the CAM system.<br>Input parameters:<br>**Msg** (string) - message text;<br>**MsgType** (**TNCMessageType**) - message type (see the description in the **Log** method). | Used to warn the user while the interpreter works. |
