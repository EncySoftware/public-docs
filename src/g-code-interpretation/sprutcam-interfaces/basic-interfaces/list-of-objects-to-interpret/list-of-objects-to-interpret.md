# List of objects to interpret

**INCT_BlockExecArray** - a CAM system interface that implements the [list of objects of the current block for interpretation](../../../translation-and-interpretation/translation-and-interpretation-g-code-based-program.md).

**Description of the interface methods:**

<table>
<thead>
<tr><th>Method</th><th>Method description</th><th>Description of use</th></tr>
</thead>
<tbody>
<tr><td><strong>Add</strong></td><td><p>The function adds an object for interpretation to the end of the list of objects and returns the index of the added object (integer).</p><p>Input parameters: <strong>ExecType</strong> (<strong>TNCExecObj</strong>) - type of the object added for interpretation; <strong>ExecParam</strong> (pointer) - parameter of the interpreted object (see the description below).</p></td><td><ol><li>When the NC program text is analyzed beyond the standard analysis of the CAM system kernel (implementation of the <strong>INCT_Interpreter.TransLine</strong> method), it makes sense to add the recognized lexemes and semantic constructs to the list of objects for interpretation (<strong>Add</strong> method) with the object type (<strong>ExecType = exObj</strong>), and to fill the <strong>ExecParam</strong> field with an array index or with a pointer to a structure storing the object data for its later interpretation.</li><li>When the next command of the current <strong>INCT_BlockExecArray</strong> list is interpreted and it is known that this command must be interpreted at the end of the block, it can be added to the list with the <strong>Add</strong> function.</li></ol></td></tr>
<tr><td><strong>Insert</strong></td><td><p>The function adds an object for interpretation to the list of objects at the number <strong>Index</strong> and returns the index of the added object (integer).</p><p>Input parameters: <strong>Index</strong> (integer) - number of the object in the list; <strong>ExecType</strong> (<strong>TNCExecObj</strong>) - type of the object added for interpretation; <strong>ExecParam</strong> (pointer) - parameter of the interpreted object (see the description below).</p></td><td>When the NC program text is translated, the translated objects can be added to the beginning of the interpretation list, or an object can be added after another required object with the <strong>Insert</strong> function, if the execution of the interpreted objects requires it.</td></tr>
<tr><td><strong>Get</strong></td><td><p>The function returns the object with the number <strong>Index</strong> from the interpretation list (<strong>INCT_BlockExecObject</strong> interface).</p><p><strong>Important!</strong> The result returned by the function is valid only until the next change of the <strong>INCT_BlockExecArray</strong> list of objects.</p><p>Input parameters: <strong>Index</strong> (integer) - number of the object in the list.</p></td><td>The <strong>Get</strong> function is needed when the objects of the list are interpreted. With it, the interface of the interpreted object (<strong>INCT_BlockExecObject</strong>) can be obtained by the object number in the list. Then, depending on the object type and purpose, the actions forming the tool path or preparing for them (storing values, initializing variables, etc.) are performed.</td></tr>
<tr><td><strong>Find</strong></td><td><p>The function searches the list for an interpretation object by the <strong>ExecType</strong>, <strong>ExecParam</strong> parameters starting from the object with the number <strong>FromIdx</strong> and returns the found object (<strong>INCT_BlockExecObject</strong> interface).</p><p><strong>Important!</strong> The result returned by the function is valid only until the next change of the <strong>INCT_BlockExecArray</strong> list of objects.</p><p>Input parameters: <strong>ExecType</strong> (<strong>TNCExecObj</strong>) - type of the interpreted object; <strong>ExecParam</strong> (pointer) - for a register, the base register number, for an object, the pointer filled by the interpreter; <strong>FromIdx</strong> (integer) - starting number of the object in the list.</p><p>Output parameters: <strong>Index</strong> (integer) - number of the found object in the list.</p></td><td><p>The <strong>Find</strong> function can be used to find out whether a register or an object is present in the already translated part of the block.</p><p>For example:</p><ol><li>To add a new interpretation object after this object (<strong>Insert</strong> function).</li><li>To determine the register type (when implementing <strong>INCT_Interpreter.DefineRegister</strong>). Example: for the Fanuc controller, in the NC program block 'G4 F100' the register 'F' is a dwell, and in the block 'G01 X10 F100' the register 'F' is a feed. When the register is determined, knowing that the translated block already contains the register G4, it can be determined unambiguously that the register 'F' is a dwell and not a feed.</li></ol></td></tr>
<tr><td><strong>MoveTo</strong></td><td><p>The function moves the interpretation object with the index <strong>FromIdx</strong> to the place in the list with the index <strong>ToIdx</strong> and returns the result (boolean). True - success, False - the object has not been moved.</p><p>Input parameters: <strong>FromIdx</strong> (integer) - index of the moved object in the list; <strong>ToIdx</strong> (integer) - target index.</p></td><td>The <strong>MoveTo</strong> function can be used to sort the list of objects for interpretation after the block is translated. For example, the Heidenhain controller has registers that are always processed at the beginning or at the end of a block regardless of their position in the NC program text.</td></tr>
<tr><td><strong>Get_Count</strong></td><td><p>The function returns the number of interpretation objects in the list (integer).</p><p>No input parameters.</p></td><td>The <strong>Get_Count</strong> function can be used when sorting the interpretation list to find out the number of list elements.</td></tr>
</tbody>
</table>

**INCT_BlockExecObject** - an interface of the CAM system (returned by the functions **INCT_BlockExecArray.Get**, **INCT_BlockExecArray.Find**) or of the interpreter (passed to the functions **INCT_BlockExecArray.Add**, **INCT_BlockExecArray.Insert**) that implements an object for interpretation.

**Description of the interface methods:**

<table>
<thead>
<tr><th>Method</th><th>Method description</th><th>Description of use</th></tr>
</thead>
<tbody>
<tr><td><strong>Get_ExecType</strong></td><td><p>The function returns the type of the interpreted object (<strong>TNCExecObj</strong>):</p><p><strong>exReg</strong> - base register;<br><strong>exObj</strong> - interpreter object;<br><strong>exProc</strong> - reserved, not used by the CAM system kernel.</p><p>No input parameters.</p></td><td><ol><li>The <strong>Get_ExecType</strong> function is used when the objects of the list are interpreted. It determines the type of the interpretation object. Depending on the type and parameter of the interpretation object, the actions forming the tool path or preparing for them (storing values, initializing variables, etc.) are performed.</li><li>The function is used to get the value when an interpretation object is added to the list.</li></ol></td></tr>
<tr><td><strong>Get_ExecParam</strong></td><td><p>The function returns the parameter of the interpreted object (pointer). If the interpreted object is a register (exReg), the parameter is the base register number. If the interpreted object is an interpreter object, the parameter passed by the interpreter when adding the object (<strong>INCT_BlockExecArray.Add</strong>, <strong>INCT_BlockExecArray.Insert</strong>) is returned.</p><p>No input parameters.</p></td><td><ol><li>The <strong>Get_ExecParam</strong> function is used when the objects of the list are interpreted. It determines the parameter of the interpretation object filled by the interpreter. Depending on the type and parameter of the interpretation object, the actions forming the tool path or preparing for them (storing values, initializing variables, etc.) are performed.</li><li>The function is used to get the value when an interpretation object is added to the list.</li></ol></td></tr>
<tr><td><strong>Get_IsUsed</strong></td><td><p>The function returns the 'interpreted' flag (<strong>IsUsed</strong>) of the object for interpretation (boolean).</p><p>True - the object has been interpreted in the current block, False - the object has not been interpreted.</p><p>No input parameters.</p></td><td>The function is used to get the value when an interpretation object is added to the list.</td></tr>
<tr><td><strong>Set_IsUsed</strong></td><td><p>The method sets the 'interpreted' flag (<strong>IsUsed</strong>) of the object for interpretation.</p><p>Input parameter: <strong>IsUsed</strong> (boolean) - True - the object has been interpreted in the current block, False - the object has not been interpreted.</p></td><td>The method can be used to force the interpretation flag of an object; in this case the object will not be interpreted.</td></tr>
<tr><td><strong>Get_IsOwn</strong></td><td><p>The function returns the 'own' flag (<strong>IsOwn</strong>) of an object for interpretation of the <strong>exObj</strong> type. For objects of the <strong>exReg</strong> type it always returns False.</p><p>True - the object has been added by the interpreter, False - the object has been added by a descendant or the parent of the interpreter.</p><p>No input parameters.</p></td><td>The function can be used in an inherited interpreter to decide whether to interpret the command itself or to pass it to the parent for interpretation.</td></tr>
</tbody>
</table>
