# Interpreter interface

**INCT_Interpreter** - the interface that must be implemented in the interpreter library. The interpreter library returns to the CAM system an object implementing this interface as the result of the **[NCT_GetInterface](../../../../interpreter-structure/interpreter-library/interpreter-library.md)** function call. Through this interface the CAM system interacts with the interpreter at all stages of interpreting the NC program text.

**Description of the interface methods:**

<tr><td><strong>GetIdentifier</strong></td><td><p>The function must return to the CAM system a string with the identifier of the interpreter library.</p><p>No input parameters.</p></td><td>When <a href="../../../interpreter-loading-and-initialization/interpreter-loading-and-initialization.md">the interpreter is loaded into memory</a>, the CAM system calls the <strong>GetIdentifier</strong> function and expects to receive the identifier of the interpreter library. Then the CAM system compares it with the library identifier from the interpreter settings file; if the identifiers match, it continues the loading process.</td></tr>
<tr><td><strong>GetRegisters</strong></td><td><p>The function must return to the CAM system the <strong> <a href="../list-of-interpreter-registers/list-of-interpreter-registers.md">INCT_RegisterList</a> </strong> interface, which implements the list of interpreter registers.</p><p>No input parameters.</p></td><td>When <a href="../../../interpreter-loading-and-initialization/interpreter-loading-and-initialization.md">the interpreter is loaded into memory</a>, the CAM system calls the <strong>GetRegisters</strong> function and expects to receive the list of interpreter registers, then calls this function for the parents of the interpreter. As a result, the CAM system forms a common list of registers taking inheritance into account.</td></tr>
<tr><td><strong>SetInterface</strong></td><td><p>The method must receive and, if the interpreter needs it, save the interfaces passed from the CAM system for later use. The method is called several times: once for each passed interface.</p><p>Input parameter: <strong>Intf</strong> (IUnknown interface).</p><p>No output parameters.</p></td><td><p>When <a href="../../../interpreter-loading-and-initialization/interpreter-loading-and-initialization.md">the interpreter is initialized</a>, the CAM system passes its interfaces to the interpreter library one by one using the <strong>SetInterface</strong> method. The passed interfaces can be used when interpreting the NC program text and provide access to:</p><ul><li>the formed list of registers <strong> <a href="../../../sprutcam-interfaces/basic-interfaces/register-list/register-list.md">INCT_SysState</a> </strong>;</li><li>management of the NC program text analysis settings <strong> <a href="../../../sprutcam-interfaces/managing-nc-program-analysis/managing-nc-program-analysis.md">INCT_Analyzer</a> </strong>;</li><li>the list of objects to interpret <strong> <a href="../../../sprutcam-interfaces/basic-interfaces/list-of-objects-to-interpret/list-of-objects-to-interpret.md">INCT_BlockExecArray</a> </strong>;</li><li>the equipment settings <strong> <a href="../../../sprutcam-interfaces/basic-interfaces/equipment-parameters/equipment-parameters.md">INCT_Equipment</a> </strong>;</li><li>the tool path generator in machine axes <strong> <a href="../../../sprutcam-interfaces/basic-interfaces/forming-of-the-toolpath-in-machine-axes/forming-of-the-toolpath-in-machine-axes.md">INCT_CLData</a> </strong>;</li><li>the tool path generator in geometric axes <strong> <a href="../../../sprutcam-interfaces/basic-interfaces/forming-of-the-toolpath-in-geometric-axes/forming-of-the-toolpath-in-geometric-axes.md">INCT_GeomCLData</a> </strong>;</li><li>interaction with the CAM system kernel serving the interpreter <strong> <a href="../../../sprutcam-interfaces/basic-interfaces/sprutcam-kernel-interface/cam-system-kernel-interface.md">INCT_Kernel</a> </strong>;</li><li>the parent interpreter <strong>INCT_Interpreter</strong>.</li></ul></td></tr>
<tr><td><strong>Initialize</strong></td><td><p>The method informs the interpreter that all CAM system interfaces have been passed and the interpreter can be initialized.</p><p>No input parameters.</p><p>No output parameters.</p></td><td>At the end of <a href="../../../interpreter-loading-and-initialization/interpreter-loading-and-initialization.md">the interpreter initialization</a>, the CAM system calls the <strong>Initialize</strong> method. The call informs the interpreter that all CAM system interfaces have been passed, and the interpreter can perform the actions needed for initialization (for example, get the numbers of the machine axes).</td></tr>
<tr><td><strong>NextOperation</strong></td><td><p>The method informs the interpreter that interpretation of the next operation begins.</p><p>No input parameters.</p><p>No output parameters.</p></td><td>The CAM system calls this method before interpreting each operation. The interpreter can perform the necessary actions (for example, initialize internal variables, set the order of processing the NC programs of the operation).</td></tr>
<tr><td><strong>TransLine</strong></td><td><p>The method passes to the interpreter an NC program block (or a part of the block, depending on the current iteration of the block translation) to try to read a token or a semantic construction from its beginning. If the interpreter has recognized a token or a construction, it must return the number of characters from the beginning of the string that make up the recognized token or construction. Otherwise, it returns 0.</p><p>Input parameter: <strong>CurrentLine</strong> (string) - the passed block or part of the block.</p><p>Output parameters:</p><ul><li><strong>ProcessedChars</strong> (integer) - the number of characters from the beginning of the string that the interpreter has recognized (the CAM system does not analyze these characters); 0 if no token or semantic construction has been recognized.</li><li><strong>NextLine</strong> (boolean) - after the translation of the current block, proceed to the translation of the next NC program block without interpreting the current one. All <strong>INCT_BlockExecArray</strong> objects of the current block are kept and processed together with the objects of the next block as a single block.</li><li><strong>BreakLine</strong> (boolean) - interrupt the translation of the current block, keeping the position in the block, and proceed to the interpretation of the formed <strong>INCT_BlockExecArray</strong>. The next translation starts from the saved position in the current block.</li></ul></td><td><p>During <a href="../../../translation-and-interpretation/translation-and-interpretation-g-code-based-program.md">the translation of an NC program block</a>, the CAM system lets the interpreter recognize a token or a semantic construction at the beginning of the current block. To do this, the CAM system calls the <strong>TransLine</strong> method of the interpreter and passes it the current block in the <strong>CurrentLine</strong> input parameter. In response, the interpreter must return in the <strong>ProcessedChars</strong> parameter the number of characters from the beginning of the passed string that make up the token or semantic construction, if it has been recognized. Otherwise, if the token or construction has not been recognized, the interpreter returns 0.</p><p>If the interpreter has recognized a token or semantic construction, it is removed from the current string <strong>CurrentLine</strong>, and the string is passed to the interpreter again by calling the <strong>TransLine</strong> method to try to read the next token or semantic construction.</p><p>If the interpreter has not recognized a token or semantic construction, the CAM system tries to determine the register and its value by the algorithm described in <a href="../../../translation-and-interpretation/algorithm-for-determining-register-and-values-in-g-code-block/algorithm-for-determining-register-and-values-in-g-code-block.md">this article</a>. After that, all the read characters are removed from the <strong>CurrentLine</strong> string, and the string is passed to the interpreter by calling the <strong>TransLine</strong> method to try to read the next token or semantic construction.</p><p>The process continues until the end of the string or until the <strong>BreakLine</strong> parameter becomes True.</p><p>If after the <strong>TransLine</strong> call the <strong>BreakLine</strong> output parameter is True, the translation of the current block stops, and the CAM system interprets the translated part of the block. That is, the <strong>INCT_BlockExecArray</strong> formed by this moment is interpreted.</p><p>If after the <strong>TransLine</strong> call the <strong>NextLine</strong> output parameter is True, then after the translation of the current block is completed, the CAM system reads and translates the next NC program block without interpreting the current block. The <strong>INCT_BlockExecArray</strong> formed by the translation of the current block is not cleared and is supplemented with the objects created during the translation of the next block. When the translation of the next line is completed and the <strong>NextLine</strong> parameter has not become True again, the <strong>INCT_BlockExecArray</strong> accumulated by the translation of the two blocks is interpreted. If the <strong>NextLine</strong> parameter is True again, then after the translation of the second block is completed, the CAM system reads and translates the third block, and so on.</p></td></tr>
<tr><td><strong>DefineRegister</strong></td><td><p>The function must search for a register by address, return the search result and the index of the found register.</p><p>Input parameter: <strong>Addr</strong> (string) - the register address.</p><p>Output parameter: <strong>Index</strong> (integer) - the index of the found register.</p><p>Result (boolean): True - the register is found, False - not found.</p></td><td><p>When <a href="../../../translation-and-interpretation/algorithm-for-determining-register-and-values-in-g-code-block/algorithm-for-determining-register-and-values-in-g-code-block.md">reading a token</a>, the CAM system tries to determine the register in the set of characters read from the NC program block. To do this, the CAM system calls the <strong>DefineRegister</strong> function of the interpreter interface and passes the read set of characters as the register address <strong>Addr</strong>. If the interpreter answers positively, the register is considered determined, and its index is contained in the <strong>Index</strong> output parameter. If the interpreter answers negatively, the CAM system tries to find the register by the address in the list of registers.</p><p>When implementing the function (<strong>INCT_Interpreter.DefineRegister</strong>), it is recommended to search for and determine only those registers that the CAM system kernel cannot determine unambiguously. In other cases, do not search and return a negative result.</p></td></tr>
<tr><td><strong>BeforeInterprete</strong></td><td><p>The method informs the interpreter that the translation of the current block is finished and its interpretation begins.</p><p>No input parameters.</p><p>No output parameters.</p></td><td>Before <a href="../../../translation-and-interpretation/translation-and-interpretation-g-code-based-program.md">the interpretation of the current NC program block</a>, the CAM system calls the <strong>BeforeInterprete</strong> method of the interpreter. The method is intended to initialize the variables and objects related to the current block, if necessary.</td></tr>
<tr><td><strong>Interprete</strong></td><td><p>The method passes to the interpreter the number of an element from the list of objects to interpret of the current block. The interpreter must interpret the passed object, that is, determine its type by the object number and, if necessary, add a command to form the tool path element(s) to <strong>INCT_CLData</strong>.</p><p>Input parameter: <strong>ExecNum</strong> (integer) - the number of the element in the list of objects to interpret (<strong>INCT_BlockExecArray</strong>).</p><p>No output parameters.</p></td><td><p>During <a href="../../../translation-and-interpretation/translation-and-interpretation-g-code-based-program.md">the interpretation of the current NC program block</a>, if the <strong>INCT_BlockExecArray</strong> list is not empty, the CAM system calls the <strong>Interprete</strong> method for each object of the list in turn. The method is intended to interpret an object from the list, that is, to form a tool path element from the previously translated object.</p><p><strong>Example for the Fanuc controller.</strong> If the passed object is a register with the address <strong>F</strong> (feed), then to change the feed of the current tool path, call the <strong>INCT_CLData.OutFeed</strong> method and pass the register value as the feed parameter.</p></td></tr>
<tr><td><strong>AfterInterprete</strong></td><td><p>The method informs the interpreter that the interpretation of the current block is finished.</p><p>No input parameters.</p><p>No output parameters.</p></td><td>After <a href="../../../translation-and-interpretation/translation-and-interpretation-g-code-based-program.md">the interpretation of the current NC program block</a>, the CAM system calls the <strong>AfterInterprete</strong> method of the interpreter. The method is intended to free the memory taken by the variables and objects related to the processed block, if necessary.</td></tr>
<tr><td><strong>EndOfProgram</strong></td><td><p>The function must return to the CAM system the end of program flag if a program end command was processed during the interpretation of the NC program text. The translation and interpretation of the NC program then stop.</p><p>No input parameters.</p><p>Result (boolean): True - the program has ended.</p></td><td>Before each call of the <strong>Interprete</strong> method, the CAM system calls the <strong>EndOfProgram</strong> function. If the function returns True, the interpretation of the current block and the translation of the rest of the NC program text stop.</td></tr>
