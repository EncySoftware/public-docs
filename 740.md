<a id="operations-sequence-behavior"></a>

## Verhalten der Operationsfolge:

Der Bereich **Operations sequence behavior** steuert, wie sich Operationen beim Berechnen oder Zurücksetzen ihres Status verhalten:

- **Reset all associated operations when operation parameters are changed.** Setzt Werkzeugwege abhängiger Operationen automatisch zurück, wenn sich ihre Eingangsdaten aus vorherigen Operationen ändern.
- **Start computation of the machining result just after the toolpath calculation.** Startet unmittelbar nach der Werkzeugwegberechnung automatisch eine Hintergrundsimulation.

<a id="tools-list"></a>

## Werkzeugliste:

Hier werden die Parameter für die [Erstellung der Werkzeugliste](13.md) festgelegt.

Die Werkzeugliste kann im Format **ODT** oder **PDF** erstellt werden.

Bei der Erstellung verwendet das System Vorlagen. Mehrere Vorlagen sind im Installationspaket enthalten. Neue Vorlagen können mit einem Textverarbeitungsprogramm erstellt werden, das ODT unterstützt. Weitere Informationen erhalten Sie beim [Support](811.md).

Das erstellte Dokument kann sofort gespeichert oder zunächst angezeigt und bei Bedarf bearbeitet werden. Deaktivieren Sie **Show tools list**, um die Werkzeugliste ohne vorherige Anzeige zu speichern.

Zum Anzeigen der Datei kann entweder das für den Dateityp zugeordnete Standardprogramm oder eine benutzerdefinierte Anwendung verwendet werden. Für einen anderen Editor geben Sie den vollständigen Pfad zur Programmdatei an.

<a id="external-nc-editor-panel"></a>

## Externer NC-Editor:

Im Bereich **External NC-editor** wird eine externe Anwendung zum Anzeigen von NC-Programmen festgelegt. Das System erkennt folgende Platzhalter in der Befehlszeile:

- **`$NCOUTPUTNAME$`**: Name der vom Postprozessor erzeugten NC-Programmdatei.
- **`$CD.**ItemName**$`**: Schlüssel für benutzerdefinierte Daten, der durch den entsprechenden Wert ersetzt wird.

Ist **Autorun NC-editor** aktiviert, wird der angegebene Editor nach der Erzeugung des NC-Programms durch den Postprozessor automatisch gestartet.

<a id="postprocessor-compatibility-settings"></a>

## Postprozessor-Kompatibilität:

Für ältere Postprozessoren kann das Ausgabeformat der Bohrzyklen angepasst werden, wenn bei der [Bohrungsbearbeitung](10100.md) die Ausgabe nicht aufgelöster Zyklen verwendet wird. **Drilling cycle format** bietet folgende Werte:

- **EXTCYCLE (recommended).** Neues Format mit erweitertem Parametersatz. Es unterstützt alle im System vorhandenen Bearbeitungsstrategien und ermöglicht eine realistische Simulation der Werkzeugbewegungen entsprechend der gewählten Strategie.
- **CYCLE (for old postprocessors).** Älteres Format für die Kompatibilität mit alten Postprozessoren. Einige Strategien, beispielsweise das Ausfräsen von Bohrungen oder die Spiralbearbeitung, werden nicht unterstützt. Jede Strategie wird als einfache Bewegung zur unteren Ebene der Bohrung simuliert.

<a id="performance-options"></a>

## Leistungseinstellungen:

**Leave one core free.** Hält bei Berechnungen mit mehreren Prozessorkernen einen Kern frei. Die Änderung erfordert einen Neustart.
