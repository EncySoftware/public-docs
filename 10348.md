# Skriptentwicklungsumgebung

Öffnen Sie **Scripts IDE** im Untermenü **Utilities** über ![Skriptentwicklungsumgebung öffnen](assets/images/download/attachments/157867746/159-28-ScriptsIde.png). Hier können Skriptmodule erstellt, gelöscht und bearbeitet sowie Objektereignissen Behandlungsprozeduren zugewiesen werden.

![images/download/attachments/157867746/image2024-7-22_17-8-36.png](assets/images/download/attachments/157867746/image2024-7-22_17-8-36.png)

![images/download/attachments/157867746/scripts_ide.png](assets/images/download/attachments/157867746/scripts_ide.png)

Links befinden sich die drei Bereiche **Objects**, **Events** und **Scripts** zur Verwaltung von Skripten und Ereignisbehandlungsprozeduren.

Der Bereich **Script units** enthält die Skriptmodule. Jedes Modul kann Programmcode in **ENCY PL** enthalten. Es stehen folgende Speicherarten zur Verfügung:

- Externe Dateien im Dateisystem des Computers. So kann derselbe Programmcode in mehreren Projekten verwendet werden.
- In die Projektdatei **.stcp** eingebettete Module. Diese können projektspezifischen Code enthalten, der von mehreren Stellen im Projekt aufgerufen wird.
- Innerhalb einer Bearbeitungsoperation gespeicherte Module. Sie enthalten Code für diese Operation. Die Operation kann anschließend mit ihren Einstellungen als Vorgabe gespeichert werden.

In der Fenstermitte befindet sich der Codeeditor. Ein Doppelklick auf einen Modulnamen im Bereich **Scripts** öffnet den zugehörigen Code. Jedes Modul erscheint auf einer eigenen Registerkarte, sodass mehrere Dateien gleichzeitig bearbeitet werden können.

Die obere Symbolleiste enthält die Funktionen zur Verwaltung der Module und Registerkarten.

**Create script** ![Skript erstellen](assets/images/download/thumbnails/157867746/embim60.png) erstellt ein leeres Skriptmodul. Der ausgewählte Eintrag in **Scripts** bestimmt, ob es in einer Operation, im Projekt oder als externe Datei gespeichert wird. Im anschließenden Dialog wird ein eindeutiger Modulname bzw. bei externen Dateien ein Dateiname angegeben.

**Open script** ![Skript öffnen](assets/images/download/thumbnails/157867746/embim61.png) öffnet eine externe Datei in der Entwicklungsumgebung und fügt sie zur Modulliste hinzu. Die Datei wird über den standardmäßigen Windows-Dateiauswahldialog ausgewählt.

**Save script** ![Skript speichern](assets/images/download/thumbnails/157867746/embim62.png) speichert die Änderungen des aktiven Editorregisters. Bei eingebetteten Modulen werden sie zunächst nur in die Operation bzw. das Projekt übernommen. Um sie dauerhaft auf dem Datenträger zu speichern, muss zusätzlich das Projekt gespeichert werden.

**Delete active script** ![Aktives Skript löschen](assets/images/download/attachments/157867746/scripts_ide_del_btn.png) löscht das aktive Skriptmodul.

**Objects** zeigt die Objekte an, denen Ereignisbehandlungsprozeduren zugewiesen werden können. Die für das ausgewählte Objekt verfügbaren Ereignisse erscheinen darunter im Bereich **Events**.

Ereignisse werden an bestimmten Stellen der Werkzeugbahnberechnung ausgelöst. Sie ermöglichen es, die Bahnerzeugung durch eigenen Programmcode zu beeinflussen. Bei jedem Ereignis wird die dem Objekt zugewiesene Behandlungsprozedur aufgerufen.

Die wichtigsten ereignisfähigen Objekte in ENCY sind Bearbeitungsoperationen. Daher ähnelt die Objektliste dem Operationsbaum des Bearbeitungsprozesses. Operationen können außerdem untergeordnete Objekte mit eigenen Ereignissen enthalten.

Eine Ereignisbehandlungsprozedur ist eine Funktion oder Prozedur in **ENCY PL**, die die beim Ereignis auszuführenden Aktionen definiert. Wählen Sie das Objekt unter **Objects** und das gewünschte Ereignis unter **Events**. Legen Sie neben dem Ereignis unter **Script unit** das Modul fest, in dem die Prozedur gesucht werden soll, und geben Sie unter **Method name** deren Namen an. Ist die Prozedur noch nicht vorhanden, kann ein leeres Grundgerüst automatisch erstellt werden: Doppelklicken Sie auf das Ereignis oder verwenden Sie ![Ereignisbehandlungsprozedur erstellen](assets/images/download/thumbnails/157867746/embim63.png). Ist unter **Script unit** ein vorhandenes Modul eingetragen, wird die Prozedur dort eingefügt; andernfalls im aktuell geöffneten Editormodul.

Menü zur Ausführungssteuerung

![images/download/attachments/157867746/scripts_ide_ctrls.png](assets/images/download/attachments/157867746/scripts_ide_ctrls.png)

Das Menü **Control** enthält Funktionen zum Bearbeiten, Prüfen und schrittweisen Ausführen von Skripten.

**Compile** ![Kompilieren](assets/images/download/attachments/157867746/scripts_ide_compile.png) prüft den Code auf Syntaxfehler.

**Run** ![Ausführung fortsetzen](assets/images/download/attachments/157867746/scripts_ide_run.png) setzt die angehaltene Skriptausführung fort.

**Reset** ![Ausführung zurücksetzen](assets/images/download/attachments/157867746/scripts_ide_reset.png) setzt Skriptausführung und Werkzeugbahnberechnung zurück.

**Run to line** ![Bis zur Zeile ausführen](assets/images/download/attachments/157867746/scripts_ide_runtoline.png) führt das Skript bis zur aktuellen Editorzeile aus.

**Pause** ![Ausführung anhalten](assets/images/download/attachments/157867746/scripts_ide_pause.png) unterbricht die Skriptausführung.

**Step over** ![Prozedurschritt](assets/images/download/attachments/157867746/scripts_ide_stepover.png) führt den aktuellen Befehl aus, ohne in aufgerufene Funktionen oder Prozeduren zu wechseln.

**Step in** ![Einzelschritt](assets/images/download/attachments/157867746/scripts_ide_stepin.png) führt den aktuellen Befehl aus und wechselt dabei in den Code eines aufgerufenen Unterprogramms.

**Step out** ![Unterprogramm verlassen](assets/images/download/attachments/157867746/scripts_ide_stepout.png) führt das aktuelle Unterprogramm bis zur Rückkehr in das aufrufende Unterprogramm aus und hält dort an.

**Add breakpoint** ![Haltepunkt hinzufügen](assets/images/download/attachments/157867746/scripts_ide_breakpoint.png) markiert eine Codezeile, an der die Ausführung angehalten werden soll.

Unten befinden sich **Messages**, **Execution log** und **Breakpoints**. **Messages** zeigt System- und Compilermeldungen, **Execution log** das Ausführungsprotokoll mit Systemmeldungen und Programmausgaben, **Breakpoints** die Liste der Haltepunkte.
